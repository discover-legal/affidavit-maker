# Deployment Guide for Render

This guide covers deploying the Affidavit Maker application to Render using Docker.

## Prerequisites

- Render account (https://render.com)
- GitHub repository connected to Render
- Auth0 application configured
- OpenAI API key
- Stripe account with API keys

## Architecture

The application is deployed as a **single web service** that includes:
- Node.js/Express backend API
- React frontend (served as static files)
- PostgreSQL database (separate Render service)

## Deployment Options

### Option 1: Using render.yaml Blueprint (Recommended)

This automatically creates all services and configures most settings.

1. **Connect your GitHub repository** to Render:
   - Go to https://dashboard.render.com
   - Click "New +" → "Blueprint"
   - Select your GitHub repository
   - Render will detect `render.yaml` automatically

2. **Update render.yaml**:
   - Edit `FRONTEND_URL` to match your Render URL (e.g., `https://your-app.onrender.com`)
   - Change `branch` to your deployment branch if not using `main`
   - Adjust `region` if needed (oregon, ohio, frankfurt, singapore)

3. **Set secret environment variables** in Render Dashboard:

   ⚠️ **CRITICAL**: These MUST be set BEFORE the first build or your login will fail!

   Go to your web service → Environment and add:

   **Backend Variables:**
   ```
   AUTH0_DOMAIN=your-tenant.auth0.com
   AUTH0_CLIENT_ID=your_client_id
   AUTH0_CLIENT_SECRET=your_client_secret
   AUTH0_AUDIENCE=https://your-api-identifier
   OPENAI_API_KEY=sk-your-api-key
   STRIPE_SECRET_KEY=sk_live_your_key
   STRIPE_WEBHOOK_SECRET=whsec_your_webhook_secret
   ```

   **Frontend Variables (REQUIRED for React build):**
   ```
   REACT_APP_AUTH0_DOMAIN=your-tenant.auth0.com (same as AUTH0_DOMAIN)
   REACT_APP_AUTH0_CLIENT_ID=your_client_id (same as AUTH0_CLIENT_ID)
   REACT_APP_AUTH0_AUDIENCE=https://your-api-identifier (same as AUTH0_AUDIENCE)
   REACT_APP_STRIPE_PUBLISHABLE_KEY=pk_live_your_key
   ```

   Note: REACT_APP_API_URL is already set in render.yaml

4. **Deploy**:
   - Click "Apply" to create services
   - Render will build the Docker image and deploy automatically

### Option 2: Manual Setup

If you prefer to create services manually:

1. **Create PostgreSQL Database**:
   - Dashboard → New + → PostgreSQL
   - Name: `affidavit-db`
   - Plan: Starter or Free (90-day trial)
   - Copy the **Internal Database URL**

2. **Create Web Service**:
   - Dashboard → New + → Web Service
   - Connect your GitHub repository
   - Settings:
     - **Environment**: Docker
     - **Branch**: main (or your deployment branch)
     - **Dockerfile Path**: ./Dockerfile
     - **Pre-Deploy Command**: `node scripts/migrate.js`
     - **Health Check Path**: `/health`

3. **Set Environment Variables**:

   Add all variables from the [Environment Variables](#environment-variables) section below.

4. **Deploy**:
   - Click "Create Web Service"
   - Wait for build to complete (~5-10 minutes)

## Post-Deployment Configuration

### 1. Auth0 Configuration

Update your Auth0 application settings:

**Allowed Callback URLs**:
```
https://your-app.onrender.com/callback
```

**Allowed Logout URLs**:
```
https://your-app.onrender.com
```

**Allowed Web Origins**:
```
https://your-app.onrender.com
```

### 2. Stripe Webhook Configuration

Add webhook endpoint in Stripe Dashboard:

**URL**: `https://your-app.onrender.com/api/stripe/webhook`

**Events to listen to**:
- `payment_intent.succeeded`
- `payment_intent.payment_failed`
- `customer.subscription.updated`
- `customer.subscription.deleted`

Copy the webhook secret and update `STRIPE_WEBHOOK_SECRET` in Render.

### 3. Frontend Environment Variables

⚠️ **IMPORTANT**: The frontend gets built during Docker build, so it needs environment variables set in Render Dashboard BEFORE building.

**Required REACT_APP_* variables (must be set in Render Environment tab):**
- `REACT_APP_AUTH0_DOMAIN` - Your Auth0 domain (e.g., your-tenant.auth0.com)
- `REACT_APP_AUTH0_CLIENT_ID` - Your Auth0 client ID
- `REACT_APP_AUTH0_AUDIENCE` - Your Auth0 API audience
- `REACT_APP_API_URL` - Already set in render.yaml
- `REACT_APP_STRIPE_PUBLISHABLE_KEY` - Your Stripe publishable key (pk_live_* or pk_test_*)

**To add/update these variables:**
1. Go to Render Dashboard → Your Web Service → Environment
2. Click "Add Environment Variable"
3. Add each REACT_APP_* variable listed above
4. Click "Save Changes"
5. Render will automatically trigger a redeploy with the new variables

**Why this matters:**
- These variables get baked into the JavaScript bundle during `npm run build`
- If not set, the React app will have `undefined` values (breaking login, payments, etc.)
- Changing these requires a full rebuild/redeploy

**Troubleshooting:**
If login shows "https://undefined/authorize", you're missing REACT_APP_AUTH0_DOMAIN.

## Database Migrations

Migrations run automatically via the **pre-deploy command** in `render.yaml`:
```yaml
preDeployCommand: node scripts/migrate.js
```

This ensures your database schema is up-to-date before each deployment.

To run migrations manually:
```bash
# SSH into Render shell (Dashboard → Shell tab)
node scripts/migrate.js
```

## Important Notes

### File Storage Options

⚠️ **PDFs are stored in `/documents` which uses ephemeral storage by default**

What this means:
- Files persist during normal operation
- **Files are deleted when you deploy/restart**
- Acceptable for MVP where users download immediately

**To enable persistent storage on Render:**
- Follow the step-by-step guide: [Render Persistent Disk Setup](docs/RENDER_PERSISTENT_DISK.md)
- Attach a 1GB (or larger) persistent disk to your service
- PDFs will persist across deployments and restarts
- Recommended for production use

**For large-scale production:**
- Migrate to AWS S3, Cloudflare R2, or similar cloud storage
- Better for horizontal scaling with multiple instances
- Automatic backups and CDN integration

### Cold Starts

On Render's free/starter plans:
- Services sleep after 15 minutes of inactivity
- First request after sleep takes 30-60 seconds (cold start)
- Upgrade to paid plans for always-on instances

### Docker Build Time

First build takes **5-10 minutes** due to:
- Installing Chromium and dependencies
- Installing npm packages
- Building React frontend

Subsequent builds use layer caching and are faster.

## Troubleshooting

### Puppeteer Errors

If you see "Chrome not found" errors:

1. Check Dockerfile includes Chromium installation
2. Verify environment variables:
   ```bash
   PUPPETEER_SKIP_CHROMIUM_DOWNLOAD=true
   PUPPETEER_EXECUTABLE_PATH=/usr/bin/chromium
   ```
3. Check logs for Chromium dependency errors

### Database Connection Errors

1. Verify `DATABASE_URL` is set correctly
2. Use the **Internal Database URL** from Render PostgreSQL
3. Check database is in the same region as web service
4. Verify database is running (Dashboard → Database → Status)

### Build Failures

1. Check build logs for specific errors
2. Common issues:
   - Missing dependencies in Dockerfile
   - npm install failures → Check package.json
   - Frontend build errors → Check client/package.json

### Runtime Errors

1. Check environment variables are set correctly
2. Verify Auth0, OpenAI, Stripe credentials
3. Check application logs for stack traces
4. Use Render Shell to debug: `node` REPL, `ls`, `cat`, etc.

## Scaling

### Vertical Scaling
Upgrade your plan for more resources:
- **Free**: 512MB RAM, 0.1 CPU (sleeps after 15 min)
- **Starter**: 512MB RAM, 0.5 CPU ($7/month)
- **Standard**: 2GB RAM, 1 CPU ($25/month)
- **Pro**: 4GB RAM, 2 CPU ($85/month)

### Horizontal Scaling
For high traffic, enable multiple instances:
- Dashboard → Your Service → Settings → Scaling
- Set number of instances (2, 4, 8, etc.)
- Render handles load balancing automatically

## Security Best Practices

1. ✅ Never commit secrets to git
2. ✅ Use environment variables for all credentials
3. ✅ Enable Auto-Deploy only for stable branches
4. ✅ Use Stripe test keys for staging environments
5. ✅ Regularly rotate SESSION_SECRET and API keys
6. ✅ Monitor logs for suspicious activity
7. ✅ Keep dependencies updated (`npm audit`)
